# 3-minute demo script

Packaging-line QA on a station screen (tabs Run / Setup / QA / Record / System) and the read-only line board (`/board`) on a second screen. The quoted banner, button and tab text is exact (it is what the running bench shows). The rule text, rule numbers, pocket numbers, batch numbers, times, the heard transcript, the agent's tool calls and its reasons are examples: they depend on what is spoken, on the approved checklist and on what the model chooses. The footer "Built with Muse Spark Open" is always on the Run screen and on the line board.

Before filming:
- Start the app fresh with a new product name (`--product`), so the line board's timeline starts with the take. Then QA logs in through the header ("Name", "Password", "Log in"). The Setup, QA, Record and System tabs appear after the login.
- Open the line board (`/board`) in a second browser window on the laptop, shown on a second monitor. Keep it on the laptop: a phone on the network loses it in the Wi-Fi-off shot. The phone stack light (`/lamp`) is only needed up to 1:36.
- Strips: a good strip; one real known-bad challenge strip, labelled C1 (for example a real strip with a broken tablet); a strip with an empty pocket; a strip with a wrong tablet; a start-up strip whose foil print matches the batch, product name and strength. The spoken rule must list each defect shown (empty pocket, broken tablet, wrong tablet).
- Off camera, between the "Approve" shot and the QA tab shot: teach the station (Setup, step 3, "Save this strip" five times), then register C1 on the QA tab ("Physical challenge set": label, defect kind, "Register challenge strip (photo from the camera)").
- Long waits (the self-test, each inspection, the agent) are cut in the edit; the times below are screen time.

Notes
- Only the shot right after the title is in Tamil; the rest is English, with English subtitles on the Tamil one.
- The line board gets two beats of about 6 s each (1:30 and 2:29), each showing a state a person must act on. It never opens the video and is not in the thumbnail.
- Type End batch counts that match what the bench saw (the challenge strip and the start-up print strip are not inspected strips): for example "Strips received" 4, "Good tray" 1, "Reject box" 3 (the two rejects and the strip held in the Wi-Fi-off shot), the rest 0. Outside a limit, End batch asks for the QA password and an investigation reason.
- Signing is refused while anything waits for a person ("Sign refused — still waiting: ..."). Before the End batch shot, approve every request the agent made: a pending request stays on the board and blocks the signature. If the agent asks for a re-teach, approving it locks the station until a self-test passes; take that shot again.
- Film from "Start batch" to the signature within one hour: a missed hourly check needs a QA review note before the record can be signed (QA tab, "Missed hourly checks: QA review note", with the QA password).
- If SAM 3.1 does not answer in a take (outside the Wi-Fi-off shot), the strip is held, not judged; keep the take as proof, or film it again.
- "Ask about the records" stays out of the video.
- Say "packaging-line QA", "tamper-evident" and "draft record — QA signs it". Give no accuracy number except what `EVAL.md` holds.
- Say "an automatic self-test every shift, on top of the physical challenge strip".
- Check the exact on-screen wording against the running bench before filming; the lines above follow the code but were not filmed.
